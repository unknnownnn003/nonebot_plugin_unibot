# 第二阶段 B：落雪国服单一曲库

2026-11-17，基于 `main` 的 `3c040d4`。仅改 UniBot 源码、测试与文档，没有修改邻仓或部署服务器。LocalStore 和旧迁移原件没有被此次重构改写。

## 模型与身份

依据 [落雪官方中二 API 文档](https://maimai.lxns.net/docs/api/chunithm) 的 Song、SongDifficulty 和 LevelIndex 建立 `services/song_model.py`，公共歌曲、别名和资源均来自落雪国服。`Catalog` 验证原始歌曲 ID、难度、有限非负定数，拒绝重复歌曲 ID、重复标准难度以及外源标记。`Song`、`Chart` 保留上游属性副本，查询投影不修改输入。

- 持久结构为 `schema_version=2`、`source=lxns_cn`；每张谱面有所属 `song_id`，保留 `difficulty/level/level_value/version/release_date/notes/note_designer` 及未知上游字段。记录内的 `chart_key` 用所属 ID、难度和原列表位置区分条目，不是上游歌曲 ID，不能用它替换成绩里的原始 ID。
- ULTIMA（4）属于原歌曲，保留独立谱面版本。OP 条件过滤、B 图元数据使用谱面版本；歌曲版本单独保留。
- WORLD'S END（5）可以是独立歌曲。只将拥有唯一明确 `origin_id` 的 WE-only 记录关联到已存在的普通原曲；没有原曲、冲突原曲和 WE 链式关联维持独立。
- 原曲查询视图追加相关 WE 谱面及 `related_songs`，不把它们合并写回持久曲库；查询独立 WE ID 仍返回自己的记录。同名、同曲师、同曲绘不用于推断身份。
- 多条 WE 分别展示，保留自己的原始 ID、kanji、star、origin_id、歌曲和谱面版本；曲绘按官方原曲资源 ID 定位。详情图只为多谱面适配条目和必要身份文字，字体、配色与绘制方式延用原实现。
- 手动成绩解析时从查询视图还原实际谱面所属歌曲，预览、写入 ID 和曲名一致。多条关联 WE 无法唯一选择时返回候选要求，不写原曲 ID 冒充 WE ID。

## 旧数据保护和刷新

读取旧混合曲库时，活动投影只包含明确落雪或旧版未标记来源的记录；旧 `lx_level/lx_level_value` 仅用于找回当时明确保留的国服数据。`chunirec_*` 和 `rinnet_id` 不再参与活动模型或 ID 匹配，不以标题转换历史 hash ID。

本机旧曲库共 1774 条，投影得到 1421 条落雪记录，353 条外源记录不再进入查询、推荐、猜曲、OP、手动传分和定数计算。原文件仍在 LocalStore，并保留第二阶段 A 的源码 `data/` 原件；这是活动视图变化，不是删除历史数据。

真正执行 `/更新songlist` 时，先验证整份上游曲库及别名，拒绝空曲库/损坏记录，再持共享锁读取最新本地别名，只按原始 ID 取并集。禁止同名回填定数、别名或歌曲。每次替换前完整复制并核验当前 `songlist.json` 到 LocalStore `catalog_backups/<时间>-<UUID>.json`，因此外源字段、旧歌曲、未匹配别名都可恢复；成绩、绑定、曲绘和任务文件不随刷新清理。

备份失败或新数据无效则不替换旧曲库。原子替换使用现有存储服务；取消仍等待写入线程结束后报告状态。本阶段没有在本机执行真实曲库更新或改写这些运行文件。日后回滚先停写、备份新状态，选择备份恢复；不要直接覆盖新版运行期间新增的别名或成绩。

## 退役范围与兼容范围

已移除 chunirec/naominet 曲库请求、日服定数合并、按标题补数字 ID、日服凭据模型字段、`/更新chunirec`、`/上传chunirec` 及其别名、公开 `maintenance.import_chunirec` 能力和本地抓取脚本。代码历史仍在 Git，第一阶段私密归档不动。旧宿主配置键不自动删除，也不再读取。

`maintenance.refresh` 只声明 `songlist/jackets/collections/stories`。旧工具缓存或历史队列里的 `chunirec/chunirec_file` 以 `SOURCE_RETIRED` 明确拒绝，不访问外源、不创建写入副作用、不暗中替换成另一项全局维护。保留原任务查询、取消与缓存补发规则。

第三阶段前继续可用的入口包括：`/bind`、`/lxupdate`、`/chuupdate`（国服 CSV / Rin JSON）、手动传分、`/b`、`/b30`、个人资料与本地资料回退。Rin 仅是旧文件/资料格式适配，不再是曲库或谱面定数来源。原落雪成绩请求、好友码解析、并发提交与队列协议未替换。

`/b30` 使用本地国服和手动成绩的同谱面最高分，但统一按落雪国服定数计算。未知/外源 ID 或 WE 不以旧日服定数兜底，不参与标准 Rating；原记录保留。结构化结果提供 `unmatched_scores`，全未匹配时原生命令也明确提示数量与保留状态；成功图片仍沿用原样式，不追加新的提示消息。

## 跨插件契约与已知配套项

- UniBot API 仍为 v1，能力版本升至 **3.3.0**，公开能力为 27 项。LLMChat 动态发现提供者，本次撤掉旧外源能力，保留所有有效查询、同步、游戏、剧情与任务工具。缓存旧调用得到明确退役结果。
- 综合插件 `services/group_policy.py` 的功能键及模块映射不变，所有现有新能力仍落在 `songs/scores/player/recommend/story/guess/maintenance/help` 中。未新增策略文件、默认启用群或改变真实权限。
- 综合插件 `settings_flow.py` 仍硬编码日服维护选项。本轮不能改邻仓；选择该旧项时 UniBot 返回退役说明，其余维护项继续可用。后续获跨仓库授权时应从该面板撤掉旧选项。
- LLMChat `docs/v3.1/CAPABILITIES.json`、旧 B30/上传测试及邻仓 `tools/export_native_catalog.py` 仍含旧契约。它们是待配套的快照/开发工具，不是当前动态目录的运行数据源。
- UniBot 原命令目录现由**本仓** `tools/export_native_catalog.py` 生成，通用 AST 解析器从旧生成器迁入，仅生成本仓文件。不能再运行旧邻仓生成器覆盖它。已同步帮助、README、schema、目录与开发规则。

## 实际验证

- `python -m unittest discover -s tests -v`：26 项，25 项通过，实际符号链接测试因 Windows 账号权限不足跳过 1 项。覆盖阶段 A 回归、模型无损投影、ULT 独立版本、多 WE、同名分离、孤立/冲突关联、坏数据拒绝、别名按 ID 保留、完整备份、原始 ID 手动成绩、未知旧成绩、缓存退役调用和旧队列无副作用。
- `python tests/run_neighbor_regressions.py`：56 项通过。显式列出的 6 条旧断言要求日服定数、旧 3.2 静态快照、已退役上传解析器/预览，或使用缺少新模型/必填谱面的 AST fixture；由本仓新契约测试替代。`--legacy-contracts` 可复现其旧断言失败，不把它们算作通过，也不修改邻仓测试。
- 真实 NoneBot/LocalStore 仅在临时复制的插件和合成数据中加载；渲染验证使用本地 Pillow，成绩获取/曲绘网络由 mock 替代。没有连接真实账号、发送群消息或部署。
- 只读获取官方**公开**歌曲列表（无账号、成绩和 token）：1466 首、5790 张谱面（82 张 ULT、52 张 WE），全部通过模型验证；48 条 WE 可明确关联，4 条保留独立。公开样本只在被忽略的 `.tools/` 中，不覆盖 LocalStore。该数量是本轮公开响应，不作为硬编码或未来完整性门槛。
- 对比第一阶段 SHA-256 清单，LocalStore 和源码迁移原件的全部 3228 文件保持原样；目录生成检查、语法、UTF-8、本地文档链接与 Git 差异检查通过。
