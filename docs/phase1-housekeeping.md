## 架构发现与下一阶段

1. 顶层模块同时含注册、网络/解析及渲染，`services/` 也反向导入顶层实现。服务层已存在，但还没有完全分离。先围绕真实改造提取共用边界，不进行机械拆分，也不能随意改模块路径：综合策略映射和生成目录使用这些名字。
2. LLMChat 通过 `agent_tools.py` 发现已加载提供者的 `llm_api`；UniBot API v1、能力版本 3.2.0，任务与成绩存储归 UniBot 所有。`services/native_catalog.py` 是邻仓工具生成物，改命令须检查生成器写入范围，不能直接手改或未经授权运行跨仓库生成。
3. 综合插件是群策略唯一所有者，并提供设置面板和全局维护入口。UniBot 独立于 LLMChat 可运行；缺少综合策略提供者时群业务默认拒绝，私聊保留原权限行为。本人任务管理与业务发送/重放的例外不同，不能互相替代。
4. 数据源并非集中在一层：曲库包含落雪、chunirec 与 naominet ID/定数；个人资料保留 Rin 回退；本地 B30 使用日服定数。删除旧来源还会影响成绩元数据、推荐/OP、原生命令、LLM schema、维护资源枚举、设置面板、帮助与配置。当前 `config.py` 有四个可选字段，原规则仅写 `lxns_token` 已修正。
5. 本地状态直接写插件目录；部署、归档和数据迁移需显式排除覆盖。同步持久任务及媒体库分别为 `data/native_jobs.sqlite3`、`data/native_presentations.sqlite3`，只在运行时创建；不能因本地不存在而省略迁移。成绩和资料单文件原子写，不具备跨文件事务。
6. OAuth 需先核验落雪当时官方协议，再定义私密授权、身份绑定、凭据存储与刷新/撤销。现有开发者 token 和好友码绑定不是 OAuth。下一阶段先做兼容与迁移设计，按明确授权配套修改三插件，不在本轮提前退役功能。
7. 本仓库没有正式打包或测试配置，跨插件隔离测试主要位于 LLMChat；依赖声明也缺少完整版本约束。下一阶段需记录可重复的依赖与测试入口，不能以邻仓历史通过记录代替本轮验证。
