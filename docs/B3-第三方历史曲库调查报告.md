## Music.xml 的可恢复范围

`name.id` 是文件中声明的游戏曲号。`type/id` 与难度标签组成谱面槽标识。`levelDecimal` 为 0–99，按百分位叠加，`level=10`、`levelDecimal=40` 表示 `10.40`。Aqua 文档、迁移和生成器的数值结构互相对应。B2 以十分位存储，解析器保留精确 Decimal，遇见 `10.75` 之类的新输入需先核实其格式，避免擅自四舍五入。`releaseTagName`、`netOpenName`、`resourceVersion` 的字段语义各异，也缺少足以跨 22 代验证文件实际生效日期的资料。早期第 4 号槽可为 WE，新时期普通谱面可在第 4 号槽有 ULTIMA。解析器优先读取明确难度标签，在无标签时要求选定有依据的 XML 布局，对歧义保留 `unknown`。`disableFlag`、`firstLock`、`exType`、谱面 `enable` 和文件路径分别记录。 [旧格式字段](https://github.com/Suprnova/Chunithm-Research/blob/main/Music.md) · [补丁目录说明](https://github.com/Suprnova/Chunithm-Research/blob/main/General.md) · [生成器](https://github.com/MewoLab/AquaNet-Assets-Scripts/blob/7375317c9bde4b6d30275c75aa0f32e2c899e0a5/chu3/all-music.ts)

恢复特定版本应以权利明确的元数据、ROM 和 data build、区域、选项包顺序与各文件哈希为基础。先解析所有来源记录，再按经证实的运行时顺序确定同曲号的有效文件。缺包、同优先级重复、改包和身份变化都应先保留争议。结合 SEGA 配信、下架和复归公告核对正式可玩日期，另以谱面指纹区分修订。原始 XML 仅能直接证明该文件里的数，文件修改时间与服务器发布时间都需要另外解释。本轮没有找到能够验证真实游戏版本且授权明确的历史原始 XML 样本。仓库测试使用自编合成 XML，验证格式、版本声明与发行标签分离、WE、禁用槽、百分位和前后差分。实证曲库比对使用公开 SQL 和静态 JSON。 [参数字段参考](https://github.com/Suprnova/Chunithm-Research/blob/main/Music.md)

## B4 建议

1. **做定向补证。** 优先把 MATE 的 382 个位置候选交叉核对明确 `diff` 的授权导出或逐谱查证资料，先处理 238 个与估算不同的值。问 MewoLab 是否可提供 2026-10-19 构建的 ROM/data build、覆盖顺序和 `enable`/`diff`，以及 B2 观察日是否发生过变更。先校准 59 张与 B2 已确认值有差异的谱面。
2. **追溯 LOST V96 的原始输入。** 问 Aqua 维护者提取区域、构建版本、末代 option 清单和生成日期。按同一 B2 Chart ID 去重，先补有可靠配信和谱面身份的行，再审核 V35 与 V96 的旧值。对 CRYSTAL 和 NEW 的 72、75 条差异分别核对修订及当期适用范围。NEW PLUS 和 SUN 的增量可用相同方法小批次验证。
3. **向 RinNET、MuNET 索取仅含公共元数据的版本清单和导出。** 需要区分账号版本选择参数、实际曲库版本、区域、ROM/data build、补丁顺序、是否保留停配曲及再利用条件。账号、卡号、个人成绩和完整游戏包都与验证无关。初代到早期 AIR/STAR 应优先找有权提供的末日 XML、分区包清单或当期独立测量。
4. **B4 值得投入小批次审核。** 首批候选应当具备可追溯的版本窗口、明确难度与修订映射、官方配信证据、来源关系和许可。全部 6,990 个候选仍缺其中至少一项，现阶段不宜批量升级。若拿到新的合法原件，先运行下一节的比较再决定范围。
